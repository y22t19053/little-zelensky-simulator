# 故事线与动态战役（v1.2.0）

这一页说明 v1.2.0 新增的故事线系统怎么工作、每局为什么不一样、哪些地方是历史资料、哪些是机制假设。

## 一、为什么要加这一层

v1.1.1 的问题是每局的结构相同：每个窗口的四五份决策文件全部来自 `js/campaign.js` 里固定的 13 个窗口，逐字相同；37 个动态事件模板彼此独立，每窗口最多抽 2 条常规事件加 1 条摩擦事件，而且多数只有「知道了」一个按钮；100 个种子抽样中只有 15 个模板真的触发过，其余 22 个绑定在特定选择上。

结论是：**重复感来自「固定考卷 + 事件彼此孤立 + 后果只体现为数值」，不是事件总数不够。** v1.2.0 因此没有去堆更多散装事件，而是把内容组织成「一条线走几个窗口、在中间做出一个改变后续的决定」。

## 二、结构

```
固定历史骨架（js/campaign.js 的 13 个窗口 + js/dynamic.js 的条件事件）
        +
故事线（js/storylines.js：8 条线，每局展开 3—4 条主轴 + 2 条辅线）
        +
有限种子变化（激活哪几条线、走哪条分支、摩擦事件落在哪个窗口）
        +
决策因果反馈（分支旗标影响后面两三个窗口的文件、动态、机构状态）
        +
通关后的历史档案（js/afterward.js）
```

每局仍然从 2022 年 2 月 24 日开始，仍然只有一个正式入口，仍然 13 个窗口、56 点注意力。改变的是每局展开哪几条线、线走向哪个分支。

## 三、八条故事线

| 线 | 标题 | 主题 | 对应的重大决策节点 |
| --- | --- | --- | --- |
| `line_airfield` | 跑道与空域 | 首都防御与设施拒止 | 安东诺夫机场 |
| `line_gov` | 命令从哪一层发出 | 政府连续性与地方治理 | 政府连续性 |
| `line_mobilize` | 登记、征用与管不过来 | 社会动员与组织能力 | — |
| `line_intel` | 两份互相矛盾的报告 | 情报迷雾与信息战 | 撤退信号判断 |
| `line_aid` | 求援的电报与迟迟不来的车队 | 国际援助与外交博弈 | 外援 |
| `line_reserve` | 手里还剩多少能动的 | 预备队与国家资源 | 预备队配置 |
| `line_civil` | 出城的路 | 民生与撤离 | 伊尔平河与撤离通道 |
| `line_withdraw` | 撤退的迹象 | 撤退判断与战役收束 | 撤退信号判断 |

每条线的阶段（`step`）由若干种节点组成：

- `brief`：免费阅读的局势动态，不消耗注意力。
- `echo`：因果回报，写「此前那个决定现在变成了什么」。
- `file`：需要总统签字的文件，消耗注意力，带多个选项与分支标签。

一条线的典型节奏是：开局信号 → 一份文件 → 分支带来的延迟影响 → 后续窗口里出现不同的动态或另一份文件 → 收束回声。

## 四、分支与互斥

每条线至少有一对互斥分支，例如机场线：

- 走「跑道拒止 / 管制 / 迟滞」→ `line_airfield_2`（工程器材向机场方向倾斜）
- 走「保留机场设施」→ `line_airfield_2b`（设施列入保护清单）

两者互斥，之后各自有对应的后续与收束回声（`line_airfield_5` / `line_airfield_5b`）。分支通过 `setFlags` 写入战役旗标，后续阶段用 `when.flags` / `when.noneFlags` 读取。

一直不打开文件的玩家不会让故事线无声消失：每份文件最后都有一项中性选项「暂时搁置，按部门现有的做法继续」（`id: 'defer'`，0 注意力），八条线各有一条兜底回声（`DEFERRED_ECHOES`），在后续窗口里写明「机场方向一直没有等到明确说法」这类后果。

## 五、每局的差异从哪来

1. **种子**：`pick(seed)` 用 `weight + rand() * 0.55` 给八条线打分，取前 4 条为主轴、接下来 2 条为辅线。主轴会产出决策文件，辅线只有免费动态。
2. **玩家决定**：分支旗标决定后面两三个窗口看到什么文件、什么动态、什么机构状态。
3. **状态条件**：`when` 里可以写 `choices`、`flags`、`noneFlags`、`minStat`、`maxStat` 等，状态不到就不出现。
4. **有限摩擦**：`js/dynamic.js` 的摩擦层仍然存在，但只提供局部摩擦，不决定战役走向。

同一颗种子 + 同样的决策序列 = 同样的展开（`tests/seeds-audit.cjs` 里有复现断言）。

## 六、内容属性

每个阶段都必须标一个 `history`：

| 值 | 含义 |
| --- | --- |
| `fact` | 已确认历史事实 |
| `reported` | 当时公开报道或当事方说法 |
| `supported` | 历史资料支持的合理决策 |
| `simulated` | 基于真实条件的模拟推演 |
| `assumption` | 为游戏机制设计的假设 |

规则：`simulated` 与 `assumption` 必须带一句 10 字以上的 `historyNote`，说明「这一段描述的是制度、资源与协调层面的合理后果，具体幅度与时间没有公开资料支持」之类。故事线里没有虚构的部队番号、兵力、伤亡数字、直接引语或可执行作战细节。

## 七、相关文件与测试

- `js/storylines.js`：数据与推进逻辑（无 DOM，可在 Node 里测）。
- `js/engine.js`：`activate` 在开局注入，`advance` 在每窗口结算时推进。
- `js/main.js`：局势动态区（`.feed`）、故事线文件徽标、结局页「本局战役故事」、探索记录。
- `tests/storylines.test.cjs`（16 项）：结构、分支互斥、降级、兜底、旗标写入、记录写入。
- `tests/seeds-audit.cjs`（100 个种子）：每窗口内容数、需注意力决策数、故事线覆盖、主线组合数、空窗口、复现性。
- `tests/routes.test.cjs`（13 项，含 3 项 v1.2 用例）：八条路线展开的故事线不同。
