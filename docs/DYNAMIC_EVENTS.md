# 动态事件系统（v1.1.0）

本文件说明 v1.1.0 新增的条件事件池：它怎么挑事件、为什么这样挑、以及写事件时的历史纪律。代码在 `js/dynamic.js`，接入点在 `js/engine.js` 的 `generateDispatches()` 与 `applyDispatchOption()`。

## 1. 为什么要做这件事

v1.0 的 13 个窗口是固定的历史骨架：同一个窗口永远是同一份情报、同一组选项。玩家第二次进战役，等于把已知答案再点一遍。v1.1 不改 13 个主窗口、不改每日回合，也不往里面塞成堆的随机选择卡；它做的是在主窗口之间插入**由你此前的决定和当前处境挑出来的**次级事件，让第二局的电报、请求和麻烦跟第一局不一样。

事件不改写历史骨架：每天的日期、四幕的推进、13 个窗口的主题与主要决策仍然是 v1.0 那一套。动态事件只能在骨架之间补充细节与因果。

## 2. 三层事件

| 层 | 数量 | 触发依据 | 作用 |
| --- | --- | --- | --- |
| 条件事件 `condition` | 28 | 此前做过的关键决策（机场、政府连续性、桥梁、预备队、外援、撤退信号） | 让「你当时怎么处理」在两三个窗口后回来找你 |
| 状态事件 `state` | 5 | 当前的兵力、协调、援助进度、事务积压 | 让处境本身变成压力，而不只是数值在动 |
| 摩擦事件 `friction` | 4 | 窗口闸门 + 模板自身概率 | 有限随机的小麻烦，制造不确定性 |

合计 37 条模板。规格要求「动态事件池 20—30 个」指的是条件事件层，本版条件事件正好 28 条落在区间内；状态层与摩擦层是在此之上额外补的两层。

摩擦事件在实现上与常规事件分开名额、分开闸门，效果也很小（多为单项 −1，或让一件手上事情更难办）：它们能改变这一局的节奏，但改变不了战役走向。

## 3. 每条事件的字段

```js
{
  id: 'dyn_runway_transport',       // 唯一 ID
  layer: 'condition',               // condition | state | friction
  window: [3, 9],                   // 可触发窗口（第 3 到第 9 个窗口）
  when: { choices: ['c_deny_runway'] }, // 触发条件
  source: '总参谋部 · 运输协调',      // 事件来源（机构 / 报告类型）
  agency: 'general_staff',          // 归口机构
  title: '跑道拒止之后的运输评估',
  info: '……',                       // 玩家能拿到的信息（只写当时可知的内容）
  needAction: true,                 // 是否需要处理
  options: [                        // 可选行动
    { id: 'road_priority', label: '……', ap: 1,
      effects: { army: 1, reserve: -1 }, coordination: 0,
      agency: 'logistics', setFlags: ['dyn_roads_priority'],
      delayed: [ /* 也允许在这里直接写延迟效果 */ ] }
  ],
  follow: 'dyn_airfield_late_damage', // 后续事件（字符串 ID，可空）
  history: 'supported',             // 历史属性：fact | supported | simulated | assumption
  historyNote: '……',                // 为什么这样归类
  replay: 'airfield'                // 对应哪个决策节点（airfield/capital/bridges/reserve/aid/signal/return）
}
```

`when` 支持的判定键：

- `choices` / `noneChoices`：此前做过 / 没做过哪些决策
- `flags` / `noneFlags`：此前写过 / 没写过哪些标志
- `minStat` / `maxStat`：某项国家状态（gov、army、kyiv、will、intl、reserve、safety）的上下限
- `minCoord` / `maxCoord`：机构协调力
- `aidAtLeast` / `aidStalled` / `aidDone`：外援到了哪个阶段
- `after` / `before`：相对窗口；`minInterventions`：亲自介入次数
- `chance`：模板自身概率（主要给摩擦层）

## 4. 事件怎么被挑出来

```js
roll(state, round)   // 返回这一窗口该出现的事件模板（0—2 条常规 + 至多 1 条摩擦）
```

1. 取本局种子 `state.campaign.seed`，对每条模板算 `hashString(seed + ':' + round + ':' + id)`——同样的种子和窗口，排出来的顺序永远一样。
2. 过滤掉窗口范围外、条件不满足、以及 `state.campaign.dyn.fired` 里已经出现过的（同一局不重复）。
3. 按散列值排序，常规层最多取 2 条。
4. 摩擦层单独判定：先看窗口闸门 `hashString(seed + ':' + round + ':friction-slot') % 1000 < 350`，再逐条过模板的 `chance`，最多 1 条。

这样做的结果：一局通常触发 10—15 条动态事件（实测近历史路线 15 条、困难路线 10 条），其中摩擦 2—3 条。

**复现性**：同种子 + 同决策序列 → 同一组事件、同一顺序。换种子只改变摩擦事件与部分条件事件落在哪个窗口，不改变「做过某个决定 → 后面会出现对应评估」这个因果。种子写在 `state.campaign.seed`，随存档一起保存，便于复盘与测试（`tests/dynamic.test.cjs` 就是靠它做的复现断言）。

## 5. 玩家能做什么、能看见什么

- 事件把一条事务电报放进「事务盘」，只有进入下一个窗口的简报阶段才能处理（和 v1.0 的电报一致）。
- 每条动态事件在表头下带一行历史属性标签，例如「资料支持的合理决策 · 桥梁是否破坏在当时确实有多种判断，双方都在权衡」。这不只是装饰：它告诉玩家眼前这段内容是史实、是合理推演，还是为了玩法设计的假设。
- 选项除了即时效果，还可以带延迟效果（1—5 个窗口后结算），记录进 `state.pending`，在后续窗口中以「到期」的形式出现在日志里。
- 未处理的事件会在下一个窗口结算窗口被自动收尾（沿用 v1.0 的 `settleOpenDispatches`），不会永远挂着。

## 6. 与决策点的对应

七个节点（`REPLAY_NODES`）与事件模板、推演模块一一对应：

| 节点 | 事件模板 | 推演模块 |
| --- | --- | --- |
| `airfield` 安东诺夫机场 | 6 条 | `rp_airfield` |
| `capital` 政府连续性 | 5 条 + 2 条状态事件 | `rp_capital` |
| `bridges` 伊尔平河与西北 | 4 条 | `rp_bridges` |
| `reserve` 预备队 | 4 条 + 1 条状态事件 | `rp_reserve` |
| `aid` 外援 | 4 条 + 2 条状态事件 | `rp_aid` |
| `signal` 撤退信号 | 2 条 + 1 条摩擦 | `rp_signal` |
| `return` 重新进入失地 | 3 条 | —（并入 `rp_signal` 的后半段） |

## 7. 历史纪律

写模板时守的几条线：

1. **不编造引语、单位、兵力。** 事件文本只写「某机构报告了什么」，不写「某将军说」的引语，也不写具体番号与数量。
2. **区分四类属性。** 每个模板必须标 `history`：`fact`（历史事实，例如 2 月 24 日机场方向的战斗确实发生）、`supported`（有资料支持当时确实存在这个判断空间）、`simulated`（基于真实条件的模拟推演，例如「若保留机场设施会带来什么安全压力」）、`assumption`（纯为机制设计，例如某项延迟结算的具体数值）。
3. **摩擦不等于战场。** 摩擦事件只能制造报告延误、道路受阻、清点差异、通信不畅这类麻烦；它们不决定机场是否守住、桥梁是否被炸、援助是否到达。
4. **争议保留不确定性。** 资料互相矛盾的说法（例如某些时点的具体战果）只写「报告之间不一致」，不选定一个数字当定论。
5. **不写事后视角。** 事件信息里不出现「后来证实」「事后看」这类措辞；事后研究只出现在战役结束后的复盘与推演室里。

## 8. 测试

`tests/dynamic.test.cjs`（13 项）检查：事件池属性完备、四类历史属性齐全、机场两条相反路线触发互斥的条件事件、后续事件接续、同局不重复、同种子复现与换种子摩擦变化、路线之间事件差异 ≥4、事务盘可处理、延迟后果进入待结算、七日模式不产生动态事件、探明记录不提前泄露内容、种子入档读回、v1.0 存档迁移。

`tests/routes.test.cjs`（10 项）用八条完整路线检查：动态事件真的在不同路线里出现不同组合，且触发记录可以追溯到层、条件与窗口。
