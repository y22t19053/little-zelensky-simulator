# 《小泽模拟器》v0.3.0 修订设计与轻量玩法审查

状态：仅供审阅。当前只实现 `design-preview/` 第一回合视觉样板，不批准、也不包含正式版本重构。

## 1. 修订后的产品设计方案

### 1.1 数据与设计假设的边界

**真实读取并核对的项目数据**（来源：`js/events.js` 的 `LZS_META.initialStats`）：

| 固定顺序 | 状态 | 初始值 |
|---|---|---:|
| 1 | 政府连续性 | 54 |
| 2 | 军队组织度 | 48 |
| 3 | 基辅安全 | 52 |
| 4 | 社会抵抗意志 | 60 |
| 5 | 国际支持 | 42 |
| 6 | 战略储备 | 52 |
| 7 | 总统个人安全 | 58 |

其他已核对值：每回合 3 AP；初始战争压力 12；第一回合为 2022-02-24“全面入侵”。第一回合四项决策的 AP 和效果均来自 `LZS_EVENTS[0]`。初始七项状态按 `getAlarms()` 核算均未触发告警。

**预览中的使用方式**：视觉样板复制以上真实初始读数，用于静态呈现；不连接引擎、不结算。正式实现时必须从现有引擎读取，不能把预览数值复制进正式逻辑。

**设计阶段假设**：以下信息架构、视觉分层、定性量级文案和夜间呈现顺序都是待审设计，不是现有机制，也不是历史统计。当前没有任何占位国家读数。

### 1.2 产品核心：从“阅读面板”改为“总统的一次值班”

保留七回合、3 AP、固定效果、延迟后果与全部历史内容，重排呈现顺序：

1. **事发**：日期、回合、AP 与有辨识度的事件视觉先建立情境。
2. **判断**：一段短情报摘要，明确“当时已知 / 当时未知”；完整情报仍可展开。
3. **签发**：决策标题和摘要尽早出现。采用 B 方案：卡片先给方向、代价和定性量级，详细情报与延迟说明可展开。
4. **夜间**：依次呈现已签发命令的实际即时结果、到期延迟效果、状态侵蚀和战争压力，不新增结算。
5. **归档**：结局后继续保留完整历史复盘、全部模拟参数和决策链。

不删历史资料，不缩短到只剩几句，也不把难度建立在系统隐瞒规则上。信息限制只来自总统视角的“当时未知”。

### 1.3 首屏与信息优先级

桌面优先级：事件与当前局势 → 当前风险 → 两项以上决策入口 → 可展开情报 → 其余状态解释。

手机优先级：日期/AP → 事件视觉与摘要 → 国家状态紧凑入口 → 第一项决策 → 后续决策。320px 允许自然滚动，不用缩小字号换取“一屏塞满”。

夜间结算应成为独立、可逐步阅读的档案页，而不是只改一个弹窗颜色。每条的数字必须来自引擎已产生的实际结果。

```text
┌ 日期 / 回合 / 3 AP ┐
│ 第一回合事件视觉   │
│ 全面入侵           │

```

折叠只改变状态的展示密度，不移除其余四项。展开后仍按原顺序显示七项。主要按钮、决策卡和折叠入口均不小于 44px。

## 3. 国家状态与决策信息披露规范

### 3.1 状态与风险

- 七项名称、顺序、0–100 数值全部使用现有状态对象；趋势来自实际结算差值。
- 告警只调用 `getAlarms()`，界面不得复制一套“看起来差不多”的危险阈值。
- 已核对的现有告警：政府/基辅 warning≤35、critical≤25；军队/意志/个人安全仅 critical≤25；国际 warning≤28、critical≤18；储备 warning≤24、critical≤14；压力 warning≥70、critical≥85。
- 崩溃和阶段结局仍只由 `checkCollapse()` / `checkFinalEnding()` 判定。颜色、图标和文案只是这些结果的视觉表达。
- 初始状态没有告警，所以预览使用中性读数，不制造“危险 52”之类的假风险。
- 手机可折叠，但摘要必须保留展开全部七项的明确入口。

### 3.2 四阶段透明度

| 阶段 | 必须展示 | 数据来源 |
|---|---|---|
| 签发前 | AP；影响方向；可能收益和代价；定性量级；延迟发生回合；情报可信度与当时未知 | 当前事件与选项定义；不把 delayed 伪装成随机 |
| 签发后 | 实际即时数值变化；命令执行反馈；互斥/剩余 AP | `applyChoice()` 已返回的结果 |
| 夜间 | 到期延迟后果；状态侵蚀；战争压力推进；每项实际数值 | `endRound()` 的实际结算记录 |
| 历史复盘 | 完整决策链；全部模拟参数；精确即时/延迟效果；历史资料与证据边界 | 决策日志、事件数据、独立历史复盘 |

建议的定性量级文案映射为设计提案：绝对值 1–3“轻微”、4–6“明显”、7 及以上“显著”；0 不显示。它只是一种格式化规则，不修改效果，也不是风险阈值。正负号必须同时显示收益与代价，不能只展示有利方向。

不新增随机效果，不隐藏精确规则来制造难度。签发前用定性语言保持总统简报感；签发后与复盘用实际数字保证可解释性。

## 4. 第一回合视觉样板与统一美术语言

样板不是“七张地图”的缩减版，而是五种视觉职能共用一套编辑语言：

| 形式 | 职能 | 约束 |
|---|---|---|
| 场景插画 | 总统办公室、电话、文件与人物处境，提供情绪焦点 | 原创、克制，不做写实伪照片 |
| 政治漫画 | 用人物和构图表现决策位置，不评价真实人物能力 | 不编直接引语 |
| 档案与电报拼贴 | 日期、密级、批示、纸张层级 | 档案装饰不冒充原始史料 |
| 战区态势示意 | 只表达事件资料已给出的城市与方向关系 | 不补未经证实的前线、兵力、路线或精确地理 |
| 国家状态数据可视化 | 显示真实读数、实际趋势和引擎告警 | 不发明阈值，不把数据条当装饰 |

统一手段：深灰与军绿底色、低饱和琥珀批示、衬线标题、等宽档案标记、硬边纸张、少量错位拼贴。禁止无意义雷达/坐标网格、霓虹光晕、廉价渐变和满屏同构圆角卡片。

本样板文件：`index.html`、`style.css`、`preview.js`、`scene-invasion.svg`。直接用本地浏览器打开 `index.html`。交互仅含卡片选中、签发栏同步和预览签发反馈。

## 5. 对原方案的修改清单

1. 删除错误的 58、62、65 等示例读数；重新从 `LZS_META.initialStats` 核对并记录七项真实值。
2. 把“签发前定性”扩展为签发前、签发后、夜间、历史复盘四阶段透明度规范。
3. 明确不新增随机性；不确定性仅来自当时情报边界。
4. 风险颜色完全服从 `getAlarms()`，结局完全服从现有判定，不设置 CSS 危险线。
5. 手机状态改为“紧凑摘要 + 七项展开入口”，不再让四项状态消失。
6. 美术从“每事件一张信息图”修订为场景、漫画、档案、态势、数据五种职能的统一系统。
7. 响应式目标从“首屏塞更多”改为“首屏理解决策”；不缩小正文，320px 允许滚动。
8. 增加实际可打开的 HTML/SVG 样板，而非只给 ASCII 和 CSS 规范。
9. 增加 29 项决策、3 AP、失败解释和 11 结局的轻量玩法审查。

## 6. 独立游戏玩法体验风险清单

本审查不修改平衡。20,000 局安全随机路线只用于发现问题，不是最优解或平衡证明；样本中 held 440 局（2.2%）、costly 15,473 局、hollow 1,760 局，其余为各类崩溃。

### 6.1 29 项决策是否有明显无效选项

没有发现“没有任何效果”或数学上必然无意义的选项；每项都有状态或延迟作用。但若以 held 为目标，一些选项的适用窗口很窄：样本 held 路线中 relocate 仅 1 次、city_defense 12 次、bunker 58 次、split 61 次、mobilize 62 次。风险是部分选项成为“看起来重要、实际很少值得签”的填充，而非真正无效。

### 6.2 是否存在固定最优路线

没有凭随机样本证明唯一固定最优路线，但存在明显的高频优势启发式。held 样本中 stay 366/440、curfew 355/440、logistics 353/440、delegate 313/440、air_defense 278/440、firepower 251/440、eu 246/440。第一回合 aid_call + address 也以较低 AP 提供多项收益。玩家可能很快背下高效组合，后续局变成清单执行。

### 6.3 3 AP 是否真正迫使取舍

有取舍：多数回合无法签完全部命令，互斥也有效。但若干 1 AP 选项效率很高，可同时签发两到三项，削弱“总统只能处理少数问题”的紧张感。样本平均签发 11.41 项。风险不在 AP 扣除错误，而在部分 AP 成本与收益效率之间的体验差异。

### 6.4 玩家能否理解失败原因

现有结局已经给出阈值依据、最终状态、决策日志和已触发延迟链，基础可解释性较好。问题是信息过长，且没有最优先突出“哪一次签发或夜间结算越过崩溃线”。军队、意志和个人安全在现有 `getAlarms()` 中只有 critical、没有 warning，预警层次也与政府/基辅等状态不同，可能让部分失败显得更突然。

### 6.5 11 种结局是否清晰合理

判定覆盖八类崩溃与 held/costly/hollow，逻辑上完整，也不是单分数结局。体验风险是 held 在随机样本中较少，而 hollow/costly 常见；玩家需要理解“存活但代价沉重”本就是主要结果谱系。阈值说明主要出现在结局后，游玩中的长期目标感知可能不足。这里只指出清晰度问题，不建议在本阶段改阈值。

### 6.6 不同组合是否产生足够不同的体验

状态、互斥、延迟和结局确实会随组合改变；但七轮事件文本与顺序固定，没有分支事件内容，差异主要落在数值管理、日志与结局。短期可重玩性来自优化路线，长期可能缺少“这次值班经历了不同故事”的感受。正式视觉重构可以增强反馈，但不能代替内容分支。
